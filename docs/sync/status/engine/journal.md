- 2026-11-24 Design of the engine (decisions, all the lead's):
  - D-a `durable` = id of the last `Persisted`; ids from one counter; a write `p` is durable iff `p <= durable`. Things that wait for a write remember its id and are re-evaluated on every call (send loop: `Rec::pid`; ops: stage pid), or hang on it as an `After` (Notify, PageDurable, Truncate, ReadyToExit).
  - D-b A page is dry-run on arrival, persisted, and committed on `Persisted` (`pipe.flight`). While one is in flight or waits for Skip frames (`pipe.stash`), other pages are dropped and read again.
  - D-c The board applies in batches `(first,last)`; a batch is applied only while the durable marker equals `{first,last,meta.attempt}`; single mode is a batch of one. After a caught panic the state is rebuilt from `pipe.pre` (a clone taken before the batch) plus `pipe.redo` (the commands applied since), not by ReadLog: the engine holds no checkpoint in memory and there is no ReadCheckpoint effect, so "from its checkpoint and log" can only be a copy the engine kept; ENG-POISON-004's point (never use the state the panic left) holds.
  - D-d `seen` is set at the membership commit (classification), the record is dropped at the board apply; so under a crash halt `U` holds records with `seen > B` (§8.2).
  - D-e `own_sealed` for a frame read back from the device's own log (a Start's tail, a replay) answers the frame's own hash when no record holds that counter: the record may be gone, and the frame was vetted when first classified. An `own_dev_foreign` found by a dry run is written to Meta ahead of the page's Persist so that a crash cannot lose it.
  - D-f The tail of a Start goes through the same dry run as a page (`Stash.from_log`), because a Skip in the tail can need frames (§17.2).
  - D-g Alarms raised during a dry run are written (WriteMeta) in a Persist emitted before the page's Persist; their Notify waits for the page's.
  - D-h Old roots after a purge (§28.2 step 4): the spec gives no persisted field for (epoch, τ_r). The engine reads the oldest base (after a purge it is the base at the purge rotation) and takes `epoch` and `epoch_clock_ms` from its membership when `epoch_seq` equals the base's seq. A device that bootstrapped after the purge keeps a root it got in its bundle: low, to list.
  - D-i `meta.prev_session` holds the current process's session id for the next process; the engine keeps the previous one in memory (§11.6 reads either way).
  - D-j `registry.restored` is part of the checkpoint (the spec says "persisted in the next WriteMeta", but Registry is a Checkpoint field); a restart recomputes it from the next welcome.
