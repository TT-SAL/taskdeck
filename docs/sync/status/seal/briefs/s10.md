# Task S10: the recovery key changes only with the current sheet (the owner's decision on O1)

Read `docs/sync/status/seal/briefs/common.md` first. Paths below are relative to the working copy.
Stage `seal` has exited. This is a change after the exit, decided by the owner on 2026-11-23
(`docs/sync/status/seal.md`, "Open questions for the owner", O1):

**The path that replaces the recovery key without the current sheet is removed** (`propose`,
`confirm`, `cancel`, the 72 hours). The path with the current sheet stays (`direct`). Rules upgrades
(§13.10) keep every rule they have.

Why: a current device can add another device by itself, and the 72 hours were measured on times that
authors write. So one compromised device could propose and confirm alone, at once, and then hold the
recovery key. A lost sheet is now answered by "Reset trust" (`device.md` §18.6).

Nothing is deployed, so no compatibility with the old layouts is kept: no reserved byte, no
placeholder field, no reader for the old form.

This task changes the specs, the crate and the vectors together, because the vectors are built by the
code and the coverage check counts the clauses.
