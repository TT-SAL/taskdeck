## Tests and vectors

- `pairing_mitm` (a gate target, no cargo feature): a relay in the middle that knows the code and
  holds every slot. It substitutes its own keys towards E, towards N or both, re-computing the MACs.
  Show that E's and N's digits then differ unless the attacker guessed them (commit, then reveal: it
  must fix its keys before it sees either side's), that N aborts after the third wrong entry, and that
  the attack goes through exactly when the digits typed into N are N's own, so six digits are the
  whole barrier; also that E never posts slot C before slot B verified, and never slot D before the
  user confirmed.
- Unit and integration tests: both machines through a whole pairing against a simulated relay and
  board; every abort of §17.11; every check of §17.6 and §17.9 failing once in order; a rotation
  racing the pairing in both orders (`seal/pair_raced`); a slot replayed under another label or
  reflected to its sender.
- `tamper`: flipping any byte of any slot, the bundle included, aborts. `contexts`: the bundle does
  not open as an entry, a blob or a file record (SEAL-CTX-003). `parsers`: `parse_code` and both
  machines over random events and mutated slots never panic.
- Vectors: `seal-pairing.json`, `seal-code.json` (§24's table).

## Rulings after the implementation (for the verify and security passes)

**What to review.** Two commits: task S6 (pairing) and task S6b, three small changes to the API of
snapshots and backups that the lead ruled after a check of the spec change (read
`docs/sync/status/seal/briefs/s6b.md` as well: its items are part of what you judge).
`git -C <W> log --oneline <base>..HEAD` names both; `git -C <W> diff <base>` shows everything.

The implementer raised eighteen spec questions. The lead's rulings; judge the code against them, and
report a place where the code does something else:

- **An event its state has no row for** aborts the machine: a slot with `seal/slot_mac` (its label is
  not the one awaited); `Snapshot`, `Entries` or `Frames` with `seal/bundle_invalid`; any other with
  `seal/pair_cancelled`. `RegisterFailed{code}` aborts with its own code. A `Tick` before the limit
  changes nothing. `Done` and `Aborted` ignore every event.
- **The code and the digits are text** (`new_code`, `ShowCode`, `ShowSas`, `CodeEntered`,
  `SasEntered`: §26): they go to a screen and come from a keyboard. The crate erases its own copies
  (`PairSecret`, the machines' state); the strings are the caller's to clear.
- **`new_code` returns the display form** `XXXX-XXXX-XXXX-XXXX-CC`; `parse_code` reads both forms.
- **A slot's framing comes before its MAC** and fails with `seal/slot_mac` (nothing is authenticated
  yet): `body_len` at most 16,040, and the slot exactly `36 + body_len` bytes. Then the MAC, label
  and role (`seal/slot_mac`), then the body's widths and layout (`seal/slot_format`).
- **Slot B's rules versions** are 1 to 16 values from 1 to 2^31 − 1, strictly ascending.
- **`Existing::start` on a bad start** returns an aborted machine and `[Abort]`, with no
  `DeleteTicket`: `seal/ctl_author` when the own device is not current in the membership,
  `seal/host_format` for an origin outside §5.4, `seal/entropy`. Whether E is halted is the caller's.
- **§17.6 check 5** also counts the cap of 256 device records (`seal/ctl_device_cap`).
- **The item of `NeedSnapshotAndRegister`** carries, as `bootstrap_seq`, the head seq E was started
  with: a placeholder. The engine composes the `DeviceAdded` with the seq of the snapshot it takes
  (`engine.md` ENG-OPS-001), and N checks `bootstrap_seq = h` at step 7
  (`seal/device_added_mismatch`).
- **`Registered` with values the bundle's table excludes** aborts E with `seal/bundle_invalid`
  (`DeleteTicket`, `Abort`), and nothing is posted.
- **The bundle's `snapshot` object has no seq**: the parser sets it to `head.seq`; §11.5's rule that
  a seq is a multiple of 64 does not apply to it.
- **`CodeEntered` after the code's check passed**: a host outside §5.4 is
  `AskAgain{seal/host_format}`, a name outside §5.5 `AskAgain{seal/slot_format}`; nothing is derived
  or fetched in either case.
- **Slot D's width** (40 to 16,040) is `seal/slot_format`, after the MAC.
- **The bundle's root and SEAL-KEY-013**: the root opens the snapshot that holds the membership
  (step 4), and step 5 checks every root against that membership's commitments before any other
  key is derived from one.
- **Step 7** also requires `bootstrap_seq = h`. A log that ends before `added_seq` is
  `seal/device_added_mismatch`; a gap, a wrong order or a seq out of place in `Entries` is
  `seal/bundle_invalid`.
- **Step 6**: an entry signed with N's own new identity (the own-dev flag) and an accepted entry
  with the commitment halt abort with `seal/bundle_invalid`; the unknown-rules halt aborts with
  `seal/pair_rules`.
- **`Entries` is the whole log from `h + 1`**, in one event (paging is the caller's); a second one
  aborts. `Frames` holds exactly the seqs asked for, each once, with the named `frame_hash`.
- **The typed digits are compared as typed**, in constant time: no normalisation.
- **Step 5 and the hash version** (raised by task S6b): the pairing machine recomputes the state
  hash from the body, so it refuses, with `seal/bundle_invalid`, a `hash_version` that the
  membership's rules do not allow (`engine.md` defines version 1 only), as the backup reader does.
- `Joined` hands out no root beyond the bundle's: the engine classifies the log from `h + 1` again
  and learns the roots of later rotations from N's own wraps. No finding.
- Duties of the caller, no findings: the engine composes and seals the `DeviceAdded`; the runtime
  sends `UserConfirmed` only after the user confirmed on E, feeds monotonic milliseconds and ticks,
  and gives N `OsEntropy`.
- Known gaps the lead hands to the fix pass, so do not report them again: §17.6 check 5 is tested
  only with 16 current devices (the cap of 256 records and `next_device_no ≤ 8191` have no test).
- The invalid cases of `seal-pairing.json` name a `base` case and give what they replace. Verifier:
  say whether another implementation can replay them from the file alone.
