## Build

1. **`open_blob`, `open_snapshot`, `open_snapshot_declared`.** Each mutates sealed bytes and then
   recomputes the hash, so every mutated input passes steps 1 and 2 of §20.5 and stops at the
   header or the AEAD. Keep that branch (it covers steps 1 to 4) and add branches, chosen by a byte
   of the input, that shape the plaintext and then seal it properly with the fixture's key (as
   `snapshot_body.rs` does with `blob::Raw`), so that the steps after the AEAD run on bytes the
   input chose: the padding (step 5); for a snapshot the inflate (step 6) and the body parser, the
   membership parser, the projection and the agreement check (step 7). In the normal mode a changed
   board or membership is refused at the recomputed state hash before those parsers run, unless
   the expected hash is the mutated body's own: where the mutated body still frames, compute the
   expected `state_hash` from its own board and membership bytes (`state_hash` is public, §26), so
   that the parsers behind it are reached. In the declared mode no hash is compared, so a mutated
   membership and history reach the parsers directly: `open_snapshot_declared` must seal mutated
   bodies under the declared key.
2. **`pair_new`.** Its fixture holds no valid slot C or D, and `n_event` builds `Entries` and
   `Frames` frames of at most 255 bytes, so the new device's machine never gets past its wait for
   slot C. Build the fixture from a whole honest run (both machines driven through the public API
   with fixed entropy, to `Done` and `Joined`), so that it holds the honest slots, the snapshot's
   parts, the log's entries and the frames a `FetchFrames` asks for. `n_event` then chooses, by the
   input: the honest event for the machine's state; a mutated copy of it (bytes changed, with the
   MAC made again under the right key where the fixture holds it, and without); an event out of
   place; a tick. Lengths read from the input allow frames of real size.
3. **`pair_bundle`.** (a) Its assertion `n_abort(..) != Some(SlotMac)` is wrong for a plaintext
   over the slot's limit (§17.4: a body of at most 16,040 bytes): there N's `seal/slot_mac` is the
   right answer. The harness expects what the spec says at each size. (b) Its helper `WithFakeE`
   draws from `OsEntropy`, so a run is not a function of its input alone: give it the fixed source.
   (c) `Code::slot` writes `body.len() as u16`, which wraps at 65,536 bytes: the helper bounds the
   body or refuses.
